# 设计与验收说明

## 1. 项目目标

项目依据《自动编程作业(1).docx》，使用 Python 标准库完成两项作业：第一题将网格路径转换为带朝向的机器人动作；第二题实现“感知—规划—行动—记忆”循环。默认环境为 5×5 网格，起点 `(0,0)`，终点 `(4,4)`，障碍为 `(1,1)`、`(1,2)`、`(2,2)`、`(3,2)`。

## 2. 模块设计

| 模块 | 主要职责 |
|---|---|
| `env.py` | 保存地图和当前位置，判断位置是否可进入，执行网格动作 |
| `planner.py` | 使用 BFS 搜索最短网格路径，通过父节点回溯生成动作列表 |
| `模块1/translator.py` | 把绝对网格动作翻译为转向及前进指令 |
| `模块1/robot.py` | 根据朝向独立执行机器人指令 |
| `模块1/robot_planner.py` | 在“位置＋朝向”状态空间搜索最少机器人指令 |
| `模块2/agent.py` | 调度感知、规划、行动和记忆，缓存并验证剩余路径 |
| `模块2/memory.py` | 记录每一步的执行前位置、动作和执行后位置 |
| `main.py` | 组织演示、打印结果并执行关键断言 |

## 3. 第一题设计

基础流程为：

```text
GridWorld → 网格 BFS → 网格动作 → 动作翻译 → Robot 执行
```

朝向顺序为 `N/E/S/W`，初始朝向为 `E`。翻译器计算当前朝向和目标移动方向之间的差值，生成零至两次转向，再生成一次 `forward`。原始网格动作和翻译后的机器人动作在独立环境中执行，最终位置必须一致。

进阶规划把状态定义为 `(position, heading)`，把三种机器人指令作为等成本边。BFS 首次到达目标位置时获得最少指令。默认地图至少需要 8 次前进和 1 次转向，因此 9 条指令是理论下界；实际规划达到该下界。

## 4. 第二题设计

Agent 每轮获取独立环境快照，然后检查缓存路径的下一步。缓存为空或下一位置不可通行时调用 BFS；否则继续复用路径。动作执行后，Memory 记录实际状态变化，再通过可选回调显示累计轨迹。

地图符号如下：

| 符号 | 含义 |
|---|---|
| `A` | 智能体当前位置 |
| `S` | 起点 |
| `*` | 已走过的位置 |
| `G` | 终点 |
| `#` | 障碍 |
| `.` | 未访问空地 |

主程序显示 1 张初始地图和 8 张逐步地图。记忆轨迹包含起点，因此默认结果有 8 条动作记录和 9 个位置。

## 5. 算法与复杂度

网格 BFS 的时间复杂度为 `O(V+E)`，父节点字典的额外空间为 `O(V)`，路径回溯长度为 `O(L)`。朝向感知规划最多存在 `4V` 个状态，复杂度仍随状态图线性增长。

第二题在静态默认地图中只规划一次；每一步仍验证最新状态。动态障碍阻断缓存路径时，Agent 会重新规划。统计项包括规划次数、展开节点数和发现节点数。

## 6. 最终验收结果

执行命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1
```

最终结果如下：

| 验收项 | 结果 |
|---|---|
| 第一题网格移动 | 8 步到达 `(4,4)` |
| 第一题基础翻译 | 10 条指令，到达 `(4,4)` |
| 第一题朝向优化 | 9 条最优指令，到达 `(4,4)`，节省 1 条 |
| 第二题自主运行 | 8 步到达 `(4,4)` |
| 第二题轨迹 | 9 个位置，包含起点 |
| 第二题地图 | 初始 1 张＋逐步 8 张 |
| 默认规划次数 | 1 次 |
| 默认 BFS 展开节点 | 19 个 |
| 动态障碍测试 | 缓存失效后重新规划并到达终点 |
| 自动测试 | 作业 1 为 5 项，作业 2 为 6 项，共 11 项，全部通过 |

## 7. 边界与限制

测试覆盖起点即终点、目标不可达、非法动作或朝向、碰撞、记忆重放、执行上限、感知快照隔离、四种初始朝向和动态障碍重规划。项目未连接真实机器人硬件，不探索未知地图，也没有图形界面。Bash 脚本已经提供，但尚未在 Linux 或 macOS 环境实测。

完整运行输出见 `terminal_log.md`；各阶段的原始需求、架构、实施和验证文档保存在 `archive/`。
